## 1. 编译链接总流程：四步原理

```mermaid
flowchart LR
    A[源文件 .cpp] -->|1 预处理| B[.i 纯源码]
    B -->|2 编译| C[.s 汇编]
    C -->|3 汇编| D[.o 对象文件]
    D -->|4 链接| E[可执行文件/库]
```

| 步骤 | 输入→输出 | 产物 | 命令 |
|---|---|---|---|
| 预处理 | `.cpp` → `.i` | 展开宏/头文件、条件编译 | `g++ -E` |
| 编译 | `.i` → `.s` | 汇编代码 | `g++ -S` |
| 汇编 | `.s` → `.o` | 机器码对象（符号未决） | `g++ -c` / `as` |
| 链接 | 多个 `.o` + 库 → 可执行/库 | 符号解析 + 地址重定位 | `g++` / `ld` |

## 2. 预处理详解

`g++ -E main.cpp -o main.i`

预处理完成：
- **展开 `#include`**：递归嵌入头文件内容。
- **展开宏**：`#define` 文本替换、`#`/`##` 操作。
- **条件编译**：`#if/#ifdef/#ifndef/#endif` 决定保留哪些代码。
- **删除注释**：`//`、`/* */` 清除。
- **插入行标记**：`#line` 维护源码位置信息（供调试与错误报告）。

要点：宏在预处理阶段是**纯文本替换**，无类型、无作用域，故工程用 `constexpr`/`inline` 替代复杂宏。

---

## 3. 编译详解

编译器（如 `cc1plus`）对预处理后的源码执行：

1. **词法分析**：把源码切分为 token（关键字、标识符、字面量、运算符）。
2. **语法分析**：按文法构建抽象语法树（AST）。
3. **语义分析**：类型检查、重载决议、模板实例化、作用域解析。
4. **中间表示（IR）生成**：转换为中间表示（LLVM IR / GIMPLE）。
5. **优化**：常量折叠、死代码消除、内联、循环优化等（受 `-O` 控制）。
6. **代码生成**：IR 转为目标机器汇编 `.s`。

- 类型错误、语法错误在此步报告。
- 模板实例化、`static_assert`、`constexpr` 求值均在编译期完成。

## 4. 汇编与对象文件

`g++ -c main.cpp -o main.o`（等价 `g++ -S` + `as`）

汇编器把汇编翻译为**机器码**并封装为对象文件。对象文件（Linux ELF / Windows COFF）包含：

| 节 | 内容 |
|---|---|
| `.text` | 机器指令 |
| `.data` | 已初始化全局/静态数据 |
| `.bss` | 未初始化全局/静态（占位，加载时置零） |
| `.rodata` | 只读常量 |
| `.symtab` | 符号表（函数/全局变量名与地址） |
| `.rela.*` | 重定位信息（待解析的外部引用） |
| `.debug_*` | 调试信息（`-g`） |

**对象文件的核心：符号表 + 重定位表**。本文件中“引用了但未定义”的符号（如调用其他 `.o` 的函数、外部库函数）被记录在重定位表中，留待链接时解析。

```bash
nm main.o        # 查看符号表
objdump -d main.o  # 反汇编
readelf -S main.o  # ELF 节信息
```

## 5. 链接详解

链接器（`ld`/`lld`/`link.exe`）把多个对象文件 + 库**合并**为一个可执行文件/库：

### 5.1 三个核心任务

1. **符号解析**：把引用符号与定义符号对应（全局函数/变量）。缺失定义 → **未定义引用错误**。
2. **重定位**：把每个节拼到最终地址空间，根据重定位表**回填地址**（把“调用某某”的占位地址替换为真实地址）。
3. **库选择**：从静态库提取被引用的成员 `.o`，从动态库记录依赖关系。

### 5.2 静态链接 vs 动态链接

| | 静态链接 | 动态链接 |
|---|---|---|
| 时机 | 链接期把库代码**拷贝**进可执行文件 | 运行期由**动态加载器**加载共享库 |
| 产物 | 自包含、单文件 | 可执行文件 + 若干 `.so`/`.dll` |
| 体积 | 大 | 小（库共享） |
| 升级 | 需重新链接 | 替换库文件即可（ABI 兼容下） |
| 依赖 | 无运行期依赖 | 运行期需能找到库（rpath/LD_LIBRARY_PATH） |
| 内存 | 每进程独立拷贝 | 库在内存共享一份 |

### 5.3 链接器查找顺序

- 命令行 `-lfoo` → 依次找 `libfoo.so` / `libfoo.a`（按搜索路径 `-L` → 系统路径）。
- 默认优先动态库；`-static` 强制静态。
- Windows 中 `.lib` 可能是静态库或动态库的导入库（需区分）。

## 6. 静态库（`.a`/`.lib`）完整实战

### 6.1 生成静态库

```bash
# 1. 编译为对象文件（不链接）
g++ -c -std=c++11 math.cpp -o math.o
g++ -c -std=c++11 util.cpp  -o util.o

# 2. 打包为静态库
ar rcs libmylib.a math.o util.o     # GNU ar：创建归档索引

# 查看库内容
ar t libmylib.a
nm libmylib.a
```

### 6.2 使用静态库

```bash
# 链接：-L 指定目录，-l 指定库名（libmylib.a → -lmylib）
g++ main.cpp -L. -lmylib -o app

# 也可直接给路径
g++ main.cpp libmylib.a -o app
```

### 6.3 静态库要点

- 静态库本质是**多个 `.o` 的归档**（含符号索引）。
- 链接器**只提取被引用的 `.o` 成员**（按需提取），未引用者不进入可执行文件。
- **顺序敏感**：`main.o` 依赖 `libmylib`，则 `-lmylib` 须在 `main.o` **之后**；库依赖库时后者在前（可用 `--start-group`/`--end-group` 处理循环依赖）。

## 7. 动态库（`.so`/`.dll`）完整实战

### 7.1 Linux：生成共享库 `.so`

```bash
# 编译为位置无关代码（PIC）
g++ -c -std=c++11 -fPIC math.cpp -o math_pic.o
g++ -c -std=c++11 -fPIC util.cpp  -o util_pic.o

# 链接为共享库
g++ -shared -fPIC math_pic.o util_pic.o -o libmylib.so

# 简写：一步生成
g++ -std=c++11 -shared -fPIC math.cpp util.cpp -o libmylib.so
```

### 7.2 Linux：使用动态库

```bash
# 编译时链接
g++ main.cpp -L. -lmylib -o app

# 运行前设置运行时库搜索路径（方式之一）
export LD_LIBRARY_PATH=$PWD:$LD_LIBRARY_PATH
./app

# 或写死 rpath
g++ main.cpp -L. -lmylib -Wl,-rpath,$PWD -o app
```

### 7.3 Windows：生成 DLL

```bat
:: 方法一：导出所有符号（dllexport）或 __declspec(dllexport)
cl /LD /EHsc math.cpp        :: 生成 math.dll + math.lib（导入库）

:: 方法二：通过 __declspec(dllimport) 显式导入
```

### 7.4 动态库要点

- **`-fPIC`**：生成位置无关代码，使库可被加载到任意地址（重定位更安全）。
- 可执行文件记录 **DT_NEEDED**（依赖库）与 **RPATH/RUNPATH**（搜索路径）。
- 运行时通过 `ldd app`（Linux）查看依赖，缺失库会报“找不到”。

## 8. 静态库 vs 动态库：区别与选型

| 维度 | 静态库 | 动态库 |
|---|---|---|
| 链接时机 | 编译期 | 运行期 |
| 部署 | 单文件自包含 | 需随带 `.so`/`.dll` |
| 启动速度 | 快 | 稍慢（加载库） |
| 内存占用 | 每进程拷贝 | 内存共享 |
| 升级维护 | 全量重链 | 替换库文件 |
| 兼容风险 | 低 | ABI 不兼容会崩（需版本管理） |
| 调试 | 直接进库源码 | 需符号（`.so` 调试版） |

**选型建议**：
- 自有内部组件、追求部署简单 → **静态库**。
- 需共享、热升级、多程序复用 → **动态库**。
- 第三方 SDK 常同时提供 `.a`/`.lib` 与 `.so`/`.dll`。
- 发布的可执行文件，避免依赖系统过新库：静态链接关键库或固定 rpath。

## 9. 链接错误定位与排查

| 错误 | 原因 | 排查 |
|---|---|---|
| `undefined reference to 'foo()'` | 符号未定义/未链接 | `nm` 检查符号；确认 `-l` 顺序 |
| `multiple definition of 'foo'` | 重复定义 | 头文件变量未 `inline`；检查全局变量 |
| `cannot find -lmylib` | 库不存在/路径错 | 检查 `-L` 与库名拼写 |
| `relocation R_X86_64_... can not be used` | 非 PIC 对象进共享库 | 加 `-fPIC` |
| `version GLIBC_2.xx not found` | 运行库版本过低 | 用兼容旧系统的构建环境 |

**通用排查流程**：`nm` 看符号 → `readelf` 看节/动态段 → 检查 `-I/-L/-l` 路径与顺序 → 检查头文件声明与定义一致。

## 10. 深入：ABI、可见性、rpath 与运行时搜索

### 10.1 ABI 与链接

- **ABI（应用二进制接口）**：符号命名规则（mangling）、对象布局、调用约定。
- GCC/Clang（Linux）共用 Itanium C++ ABI；MSVC 用自有 ABI → **跨编译器不可混链**。
- C++ 符号经 **name mangling**（如 `foo` → `_Z3foov`）编码类型信息；C 函数用 `extern "C"` 避免 mangling 以跨语言互操作。

### 10.2 符号可见性（visibility）

```bash
g++ -fvisibility=hidden -shared lib.cpp -o libx.so    # 默认隐藏
# 显式导出用 __attribute__((visibility("default")))
```

控制导出面：只暴露公共 API，减少符号冲突与二进制体积。

### 10.3 rpath 与运行时搜索

- **RPATH**（编译期写死，`-Wl,-rpath,dir`）vs **RUNPATH**。
- Linux 搜索顺序：`LD_LIBRARY_PATH` → RPATH/RUNPATH → 系统缓存（`ldconfig`）。
- Windows：DLL 搜索顺序为可执行目录 → 系统目录 → PATH 等。
- 发布时把动态库与可执行文件放同目录，或用 rpath 指向相对路径（`$ORIGIN`）。

```bash
g++ main.cpp -L. -lmylib -Wl,-rpath,'$ORIGIN/lib' -o app
```
