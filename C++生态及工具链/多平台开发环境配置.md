## 1. 平台差异总览

| 维度 | Linux | Windows |
|---|---|---|
| 编译器 | GCC / Clang | MSVC（cl.exe）/ MinGW-w64 |
| 标准库 | libstdc++ / libc++ | MSVC STL |
| 构建 | Make / Ninja / CMake | CMake / Visual Studio / Ninja |
| 库文件 | `.so` / `.a` | `.dll` / `.lib` |
| 可执行 | ELF（无扩展名） | PE（`.exe`） |
| 调试 | GDB | Visual Studio / WinDbg / VS Code |
| 包管理 | 系统包 + vcpkg/Conan | vcpkg / Conan / NuGet |
| 线程库 | `-lpthread`（pthread） | Win32 线程（std::thread 封装） |

**核心统一策略**：用 **CMake + 条件编译 + 平台抽象层**，让同一份源码在双平台构建。

## 2. Linux 环境配置

### 2.1 安装工具链

```bash
# Debian/Ubuntu
sudo apt update
sudo apt install build-essential      # g++、make、libc 开发文件
sudo apt install cmake ninja-build    # 构建系统
sudo apt install gdb                   # 调试器
sudo apt install git                    # 版本控制
sudo apt install libstdc++-*-dev       # 标准库开发文件
```

- `build-essential` 包含 `gcc/g++/make` 及基础头文件。
- 需要更新的编译器可启用工具链 PPA（Ubuntu Toolchain）或安装 Clang。

### 2.2 验证

```bash
g++ --version
cmake --version
gdb --version
```

### 2.3 常用构建

```bash
mkdir -p build && cd build
cmake -S .. -B . -DCMAKE_BUILD_TYPE=Release
cmake --build . -j$(nproc)
```

## 3. Windows 环境配置

### 3.1 路线 A：Visual Studio（MSVC，推荐）

1. 安装 **Visual Studio Build Tools** 或 Visual Studio（勾选“使用 C++ 的桌面开发”）。
2. 包含：MSVC 编译器（`cl.exe`）、MSBuild、Windows SDK、CMake 集成、vcpkg。
3. 使用 **开发者命令提示符** 或 VS 自带 CMake 支持。

```bat
:: 开发者命令提示符中
cl /std:c++20 /EHsc main.cpp
cmake -S . -B build
cmake --build build --config Release
```

### 3.2 路线 B：MinGW-w64（GCC，跨平台一致）

```bat
:: 用 MSYS2 安装 MinGW-w64 GCC
pacman -S mingw-w64-x86_64-gcc mingw-w64-x86_64-cmake mingw-w64-x86_64-ninja
```

MinGW 用 GCC/Clang 语法与 Linux 一致，便于复用同一套构建脚本；ABI 与 MSVC 不同，勿混链。

### 3.3 vcpkg 全局集成（Windows）

```bat
git clone https://github.com/microsoft/vcpkg
.\vcpkg\bootstrap-vcpkg.bat
.\vcpkg\vcpkg integrate install      # 集成到 Visual Studio
```

## 4. 双平台统一：CMake 与跨平台工程组织

### 4.1 推荐目录结构

```text
project/
├─ CMakeLists.txt
├─ vcpkg.json / conanfile.txt     # 依赖声明
├─ include/                       # 公共头文件
├─ src/                           # 源码
├─ tests/
└─ CMakePresets.json              # 平台预设
```

### 4.2 CMakePresets（统一配置入口）

```json
{
  "version": 6,
  "configurePresets": [
    { "name": "linux-release", "generator": "Ninja",
      "binaryDir": "${sourceDir}/build/linux-release",
      "cacheVariables": { "CMAKE_BUILD_TYPE": "Release" } },
    { "name": "windows-release", "generator": "Ninja",
      "binaryDir": "${sourceDir}/build/windows-release",
      "cacheVariables": { "CMAKE_BUILD_TYPE": "Release" } }
  ]
}
```

```bash
cmake --preset linux-release
cmake --build --preset linux-release
```

### 4.3 双平台 CMake 关键设置

```cmake
if(WIN32)
  add_compile_definitions(WIN32_LEAN_AND_MEAN NOMINMAX)   # 避免 Windows 宏污染
endif()

if(MSVC)
  target_compile_options(app PRIVATE /W4 /permissive-)    # MSVC 严格模式
else()
  target_compile_options(app PRIVATE -Wall -Wextra)
endif()

find_package(Threads REQUIRED)     # 跨平台线程库
target_link_libraries(app PRIVATE Threads::Threads)
```

## 5. 路径、宏与平台隔离

### 5.1 平台宏

| 宏 | 平台 |
|---|---|
| `_WIN32` | Windows（32/64 位） |
| `_WIN64` | Windows 64 位 |
| `__linux__` | Linux |
| `__APPLE__` | macOS |
| `__GNUC__` | GCC/Clang |
| `_MSC_VER` | MSVC |

```cpp
#ifdef _WIN32
  #include <winsock2.h>
  using socket_t = SOCKET;
#else
  #include <sys/socket.h>
  using socket_t = int;
#endif
```

### 5.2 路径差异

- 路径分隔符：Windows `\`，Linux `/`。用 `std::filesystem::path`（C++17）或 CMake 统一。
- 换行：Windows CRLF，Linux LF。Git 配 `.gitattributes` 统一。
- 大小写：Linux 区分大小写，Windows 不区分。

### 5.3 平台差异典型点

| 差异 | Linux | Windows |
|---|---|---|
| 线程 | pthread / std::thread | std::thread（封装 Win32） |
| 文件锁 | flock/fcntl | LockFile |
| 动态库导出 | `-fvisibility` | `__declspec(dllexport/dllimport)` |
| 控制台 | `printf`/`std::cout` | 同 |
| 路径 | `/` | `\`（用库抽象） |

## 6. 交叉编译与 CI

### 6.1 交叉编译（Linux → 其他）

```bash
# 用 CMake 工具链文件
cmake -S . -B build \
      -DCMAKE_TOOLCHAIN_FILE=cmake/toolchain-arm.cmake
```

工具链文件指定编译器、sysroot、目标架构。

### 6.2 CI 双平台（GitHub Actions 示例）

```yaml
strategy:
  matrix:
    os: [ubuntu-latest, windows-latest]
steps:
  - uses: actions/checkout@v4
  - name: Configure
    run: cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
  - name: Build
    run: cmake --build build --config Release
  - name: Test
    run: ctest --test-dir build
```

### 6.3 发布二进制

- 静态链接关键库减少运行期依赖。
- Windows 动态库与可执行放同目录或设置 DLL 搜索路径。
- 提供 `.tar.gz`（Linux）、`.zip`（Windows）。

## 8. 最佳实践与常见问题

### 8.1 最佳实践

- **统一 CMake** 作为构建入口，双平台一致。
- **显式 `-std`**，避免默认标准漂移。
- **平台差异集中**到抽象层（文件/网络/线程），业务层不写 `#ifdef`。
- **CI 双平台矩阵**构建 + 测试，尽早暴露差异。
- **依赖用包管理**（vcpkg/Conan）声明，提交锁定版本。
- 用 `CTest` + Sanitizer 在 CI 做内存/线程检查。

### 8.2 常见问题

| 问题 | 对策 |
|---|---|
| Windows 编译报大量宏冲突 | `WIN32_LEAN_AND_MEAN`/`NOMINMAX` |
| 换行/路径差异 | 统一 LF、用 `std::filesystem` |
| MSVC 与 GCC 警告不同 | 条件设置告警 |
| 找不到 `-lpthread` | 用 `find_package(Threads)` |
| DLL 找不到 | 同目录部署 / PATH / 静态链接 |
| ABI 不兼容 | 统一编译器；对外用 C 接口 |
